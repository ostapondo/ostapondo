on a Mac.

Last time I showed the app as separate panels sized for a phone, which made it impossible to picture as one window. These are whole screenshots — the full window and the full desktop, drawn at Mac size and rendered at 2×.

Everything is at real system sizes: 13 px body text, 11 px secondary, a 38 px unified toolbar, a 220 px sidebar, 12 px traffic lights. Tap any image to open it and zoom in.

01 The window

The Zones page. A vibrant sidebar with the traffic lights over it, a unified toolbar, then the set, the canvas and grouped settings — the pattern System Settings uses.

The five rectangles are the actual geometry of the set, and each carries its fraction — 0.46 × 1 is exactly what an agent sends over MCP to place a window there. The interface and the API say the same number, so nobody has to translate between what they see and what they script.

02 Desks

Each card draws the monitors it will rebuild, in the colours of the zones the windows return to. You can tell two desks apart without reading either name.

03 Mid-drag, on the desktop

This is the one that answers what the app is for. The overlay is translucent, so your own windows stay visible underneath it, and the one in your hand has already landed inside zone 2 — with the gap showing.

Two details worth arguing about before this gets built. The overlay tint is 34% for the zones you are not over and 60% for the one you are — enough to read the difference at a glance without hiding the window you are aiming at. And the dropped window sits inside zone 2 rather than filling it, because the gap is real space Plonk keeps around every window; here the zone colour becomes the frame that proves it landed.

04 The menu bar

At rest, with the panel open. The grid at the top is the live set, and tapping a rectangle sends the front window there — a fourth way to place a window, next to drag, key and voice.

Compare this with shot 03: the windows are in exactly the same places, because they are in the same zones. That is the whole product in two frames — the overlay is a promise, and the desktop at rest is the promise kept.

· How these were made

Not drawn in a design tool. There is one HTML file with real macOS metrics, and a script that opens it in Chromium at 2× and screenshots each scene by element. So the mockups cannot drift away from the design — change a colour token and every shot re-renders from it, the same way the README banner does. Both scripts are in the repository.

The honest caveat. A gradient behind every zone is drawn on every frame of every drag. On Apple silicon that is nothing, but it is worth measuring on an Intel Mac before committing — and it degrades gracefully, since flat fills in the same five hues keep the whole colour-is-the-number idea intact.
